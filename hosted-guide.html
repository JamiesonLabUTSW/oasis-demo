Two ways to run OASIS

Cloud or local?

Use the cloud demo for this session. A local installation is an optional next step for running your own stack.

Cloud hosted · Ready to join

Benefit: browser-only access, prepared examples and model access; the host handles setup.
Tradeoff: internet required, external AI services, shared capacity and a temporary trial.

Use the hosted quick start →

Local install · Set up your computer

Benefit: control your own OASIS instance, files and configuration.
Tradeoff: a matching installation kit, Docker and sufficient hardware; you manage maintenance, model setup and any provider costs.

Get an assisted installation kit →

Where AI runs: A local OASIS installation can still use cloud AI APIs. Fully offline use needs a separately configured and tested local model with enough hardware.

Quick start · Use what is ready

Three steps to your first result. One more to learn something.

Bring a browser and internet access. Your invited account already has a starter group, a rubric, a completed run and two grading providers. Review that run first; then change one thing and run again.

1

Sign in

Open the demo above and use the email and password supplied by your facilitator. Ignore Create Account. Open Grading. Sign-in help →

2

Open your completed starter run

Under Grading Runs, open the finished Trial documentation quality run with View Results. If none exists, select your starter group and that rubric and choose Start Grading once. Grading steps →

3

Review and export

Compare each score with the note and save your review. Choose Export Excel and open the workbook. Review steps →

4

Change one thing and run again

Edit, enhance, transform or draft a rubric, run it on the same note, compare the two exports, then try another model. Second pass →

Choose a note→Check the rubric→Open the run→Review→Export→Change the rubric→Run again→Compare→Another model

What your account already has

  • Two grading providers, ready to use: Google Gemini (the default, gemini-3.6-flash) and Azure OpenAI (gpt-5.6-terra). Both are shared quotas: if a run errors during the hands-on block, wait a minute and retry once.
  • A starter group with one fictional chest-pain note, the Trial documentation quality rubric (six criteria, scores 1 to 3) and one completed Gemini run. A CDC demonstration group with public-domain video and audio and its matching rubric. In the shared library, the Note Documentation Clinic 2026 activity holds seven more fictional notes for Groups → Search Encounters.
  • How runs are identified: by rubric name and start time. The runs list does not show the rubric version, and the model appears only under Details → Cost Estimate. Note the start time before you change anything.
  • Wayfinder writes rubrics; you run them from Grading. It can draft and upload a rubric. It cannot start grading, read results or edit an existing rubric in place.
  • Your own account: groups, rubrics, runs, reviews and exports stay in it. Other participants cannot open them; the host administers the whole service. Save exports before the closing time your facilitator announces.

1

Sign in to the shared demo

  1. Open the hosted MAPLES demo in a new tab ↗. Keep this guide open alongside it.
  2. Enter your assigned Email and Password, then choose Sign In. Ignore Create Account on the sign-in page: public registration is closed, and it returns an error.
  3. Look for Groups, Rubrics, Grading and Wayfinder in the MAPLES navigation.

The examples are shared across the session. Use your own assigned account for your groups, rubrics and runs. If a starter workspace is missing, ask the facilitator to finish preparing it.

Checkpoint: you are signed in as your assigned account and can open Groups and Rubrics.

Use the hosted link, not a localhost address from an older laptop guide. No private login-helper file needs to be downloaded or shared.

2

Choose one prepared note

A group is the set of encounters you want to assess together. Your account owns a starter group with one fictional chest-pain note. Use it for both passes, so that the only thing you change is the rubric or the model.

Create your own group from the shared library
  1. Open Groups → Search Encounters. Leave Elephant origin at its deployment default.
  2. Type an Activity or Case label from the shared library, for example the Note Documentation Clinic 2026 activity. Press Enter to add a filter, then select Search Encounters. Ask the facilitator if a label you expect is not listed.
  3. Select one approved synthetic note encounter.
  4. In Enter group name, use a name you will recognize that includes your account label, then choose Create Group.

The default source may include the words “local stack.” In this hosted demo, that means the server’s prepared library.

Checkpoint: your group contains the intended note. You can identify its activity and case.

Encounter uploads are handled by the administrator. You can use the preloaded catalog without uploading files.

3

Understand the rubric first

A rubric defines the questions, evidence and score anchors used to assess the note. A station is a section of the rubric matched to a case.

  1. Open Rubrics and choose View on Trial documentation quality, the prepared Note rubric.
  2. Check its station, version and criteria: six documentation criteria, each scored from 1 to 3.
  3. Read the score anchors. Decide what evidence would justify each score before asking a model to assess it.
Checkpoint: you know which rubric version you will use and what its criteria ask for.

Use the prepared rubric for the first pass. Step 7 covers five ways to change it.

4

Open your completed run, or start one

Every account begins with one completed Trial documentation quality run on the starter group, graded with the default Gemini model. Open Grading, find it under Grading Runs, note its start time and choose View Results. If no completed run is listed, start one:

  1. Select your Group and Rubric; the rubric selector shows its version.
  2. Leave Model Config alone for this first run, so your later comparison has a clear baseline; the default is Google Gemini, gemini-3.6-flash. Step 10 changes it. For a note-only run, leave Localizer and Mosaic Videos off.
  3. If you see Station mapping required, choose Confirm Mapping. Match the activity/case to the Documentation station, then confirm. Look for Mapping confirmed.
  4. Choose Start Grading once. Follow progress under Grading Runs.
  5. When it completes, choose View Results.
Checkpoint: one completed run is open, and you have noted its start time.

What to expect: one note-grading run takes roughly 30–40 seconds when the service is quiet, on either provider. It takes longer when the whole room runs at once; timing for a full cohort has not been measured. A queued run is still in progress. Use Refresh or Details to check it; repeatedly pressing Start Grading can create extra work. If it fails, share the run ID and error with the facilitator.

5

Read the evidence. Make the call.

Open an encounter in the results and select its Notes tab. Compare the original note with each AI assessment, its rationale and the rubric’s score anchors.

If you agree

Choose Accept AI for the item after checking its evidence and score.

If you would change it

Choose Review, select a permitted score in Run Scoring Guide, add optional Comments, and choose Save Review.

Reviewed Score is filled from the score anchor you select. A completed model run alone does not mean anyone has reviewed its results: the model’s output is a proposal, and your saved review is the record.

Checkpoint: the saved review reflects your judgment. Refresh and confirm it remains.
6

Export and open the workbook

  1. Choose Export Excel in the results view.
  2. If Export Incomplete Review? appears, choose Cancel to finish reviewing, or Export Anyway to download an incomplete review. Unreviewed rows have blank reviewed scores.
  3. Open the downloaded workbook and confirm the expected note, rubric items and review values are present. The file name begins with pipeline_results_ and includes the short run ID; keep it, because you will export a second run in Part 2.
Checkpoint: you have opened a real export and can explain one score using evidence from the note.

This is a temporary trial. Save the work you want to retain before the closing time your facilitator announces.

Part 2 · 15–25 minutes

Change one thing and run again.

You have a completed run and its export: that is your baseline. Now change the rubric one way, run the same note again, and see what changes. Change only one thing at a time: the rubric in Part 2, the model in Part 3.

7

Pick how you will change the rubric

All five routes produce something you can select in Grading. Choose one. Keep the original rubric and version untouched; you will compare against it.

A · Edit in Excel

Full control over criteria and anchors · No AI

  1. Open Rubrics, find Trial documentation quality and choose Download. Keep a copy of the original workbook.
  2. Open the .xlsx file in Excel and edit one question or score description. Keep the station sheet name and the ItemKey values stable so the two runs line up. Save as .xlsx.
  3. Choose Upload New Rubric. In the Upload Rubric dialog, use the Replace Existing tab to add the next version under the same name, or New Rubric to upload it under a distinct name. Check that Min Score matches the original scale: keep it at 1 for this rubric (the scores run from 1 to 3).
  4. Choose your edited workbook and complete the upload.

Starting from scratch? Two ways to make a rubric the app can ingest.

If you like spreadsheets: download the template, keep the column names and the Station1 sheet name (rename it to match your station if you set a mapping), one row per criterion, a unique ItemKey, at least two response descriptions, then Upload New Rubric → New Rubric. If you would rather describe it: open Wayfinder or Create Rubric, describe the case and the criteria, and it writes and uploads the rubric for you. Either way, finish with View to check the anchors before you run.

Download rubric template (.xlsx)Download the sample rubricWhat is in these files →

The template has three sheets (_metadata, _mapping, Station1) with the full column set and one placeholder row. The sample rubric is the same six-criterion workbook the hosted demo loads as Trial documentation quality. Both are lab-authored fictional teaching material under this repository’s academic-use license, not validated instruments.

Workbook format and score scale

Use one sheet per station. Keep these exact column names: ItemKey, Mode, Section, QuestionText, Response1, Response2. Add Response3 and later levels in order if needed. Each item needs at least two nonblank response descriptions with no gaps.

Use Note for this exercise. Each ItemKey must be unique within its station. Min Score sets the score for Response1; the next response receives the next integer. For a 0/1 rubric, set Min Score to 0. Do not add “N/A” placeholder score levels.

The app’s User Guide → Rubric Format Guide describes optional columns and other modalities. This upload accepts Excel .xlsx files. Wayfinder uploads its own drafts directly.

Versions: what Replace Existing does

Replace Existing creates the next version under the same rubric name. Earlier runs remain associated with their original version, and the runs list does not show version numbers, so note which version each run used. The rubric selector in Grading shows name (vN); check it before rerunning.

B · Enhance

The next version of the same rubric, with the suggestions you accept · Uses AI (Gemini)

  1. On the rubric card, choose Enhance.
  2. Pick an Enhancement type: Review rubric quality, Improve scoring anchors, Fill missing fields or Expand techniques and purpose. There is no free-text instruction.
  3. Choose Generate Enhancements. Read each suggestion and Accept the ones you agree with, or Accept All. Accepted changes become the rubric’s next version.

C · Transform

A brand-new rubric (v1) built on the original’s structure · Uses AI (Gemini)

  1. On the rubric card, choose Transform.
  2. Enter a New rubric name, an optional Target station, and a Target scenario in free text: the case, the learner level and the scoring emphasis you want.
  3. Choose Create Transformed Rubric.

D · Wayfinder

A brand-new rubric (v1) from a conversation · Uses AI (host-provided model) · One request at a time

  1. Open Wayfinder in the left navigation, or the chat bubble, and describe the rubric. Ask for a draft first.
  2. Review and refine the criteria and score anchors.
  3. When satisfied, say “upload it”. Confirm the banner Rubric upload succeeded., then find and View it under Rubrics.

Draft a note-documentation rubric for a chest-pain post-encounter note written by a medical student. Five criteria: history of present illness, pertinent negatives and risk factors, physical exam relevance, assessment with a ranked differential, and plan with follow-up. Use a 1 to 3 scale with one sentence per anchor. Show me the draft before uploading.

This is an original instructional prompt, not a validated assessment instrument. Wayfinder writes rubrics; you run them from Grading. It cannot start grading, read results or edit an existing rubric in place. If a request times out, refresh Rubrics and look for the new item before trying again; chat history can clear on refresh, but an uploaded rubric is saved.

E · Create Rubric form

The same as D, without the conversation · Uses AI, as D

  1. Open Rubrics → Create Rubric.
  2. Enter a Name, tick Note under Modalities, and describe the case and criteria in Details.
  3. Choose Submit. Submit generates and uploads the rubric; it is not a preview. Reopen its View page before using it.

What to expect: Wayfinder replies in roughly 2–20 seconds; Enhance and Transform are single model calls of a similar order. Routes B and C use Gemini through the model access prepared for your account; the Model Config choice on the Grading page does not apply to them, and they cannot be pointed at Azure. If Wayfinder is unavailable, use route A.

Checkpoint: Rubrics lists your new version or your new rubric.
8

Check what you made, then run it on the same note

  1. Open Rubrics and choose View on the new rubric or version. Confirm the criteria and anchors say what you meant. Note its version badge: v2 for a replaced or enhanced rubric, v1 for a new one.
  2. Open Grading. Select the same Group as your first run, then the new Rubric; the selector shows name (vN).
  3. If Station mapping required appears, choose Confirm Mapping, pick the Documentation station for the chest-pain case, and wait for Mapping confirmed. A new rubric, and often a new version, asks for this again.
  4. Leave Model Config as it was for the first run, so the rubric is the only change.
  5. Choose Start Grading once. Expect 30–40 seconds when the service is quiet; longer when the room runs together.
Checkpoint: Grading Runs lists two completed runs on the same group, one per rubric, and you know the start time of each.
9

Compare the two runs

There is no side-by-side view in the app. Compare by hand:

  1. Open both runs from Grading Runs with View Results and read the same criterion in each: the score, the rationale and the evidence it cites.
  2. Choose Export Excel from each run; Export Anyway is fine for an unreviewed run. Each file name begins with pipeline_results_ and includes the short run ID.
  3. Put the two Original Score columns next to each other by ItemKey. Keep Reviewed Score as your judgment, not the model’s.

Ask: did the rubric change move the score, or only the rationale? A change in either direction, or no change at all, is a legitimate result. The model’s output is a proposal; your saved review is the record.

Checkpoint: you can point to one criterion and say what changed between the two runs and why you think so.

If you use an external comparison tool, first check one actual MAPLES export with the facilitator. Match item IDs, rubric versions and score scales; workbook compatibility has not been verified.

Part 3 · 5 minutes

Same rubric, different model.

Now hold the rubric still and change the model. The default comparison is a second Gemini model; Azure OpenAI is the optional one if time allows.

10

Try another model

  1. Open Grading and select the same Group and Rubric as a run you already have. Once the rubric is selected, choose Model Config.
  2. In the Model Configuration dialog, untick Use server defaults. In the Note Grading row, keep Provider = Google Gemini and set Model = gemini-3.5-flash-lite. Leave the other rows alone. Choose Save Configuration.
  3. Choose Start Grading once. About 30–40 seconds when quiet.
  4. Optional: repeat with Provider = Azure OpenAI and Model = gpt-5.6-terra. About 40 seconds.
  5. Confirm which model produced each run: under Grading Runs, open the run’s Details and read the Model column under Cost Estimate. The results page does not show the model, so note the start time before you switch.
  6. Compare as in step 9: same rubric, same note, different model.

The default is Google Gemini / gemini-3.6-flash; the Postprocessing step stays on Gemini whichever grading model you choose. Media criteria are Gemini-only: Azure models grade notes and transcripts, not video. Both providers are shared quotas; if a run errors, wait a minute and retry once. Do not expect a particular difference between models: see what changes, then decide what you think.

Checkpoint: you have two runs of the same rubric on the same note under different models, and Details names the model for each.

Beyond the prepared examples

Bring your own note

Rubrics you upload, enhance, transform or draft stay in your own account; see step 7 and the rubric template. New encounter data goes through the host, who adds files to the shared encounter library.

Add a new note with your host

  1. Prepare one small .txt file with original fictional content. You can also use a public practice note from this site.
  2. Give the file to the facilitator through the session’s agreed channel, along with a short Activity label and Case label. Say which rubric station should assess it.
  3. The host uploads the note and returns the exact Activity/Case labels. The encounter becomes part of the shared demo library, so use material suitable for everyone in the session.
  4. Open Groups → Search Encounters, filter by those labels, select the new encounter and create a group. Continue with your rubric and station mapping.

Participant accounts do not show the administrator’s upload form. That is expected. Keep real patient or learner records and institutional workshop packets out of this public/synthetic trial.

Facilitator: upload a small note
  1. Sign in with the host’s administrator account and open Encounters → Upload encounter.
  2. Complete Learner full name, Learner email, Cohort, Activity, Case, Date and Time. Use fictional demo identifiers.
  3. Choose the nonempty text file and explicitly select Notes (.txt) as its type; text files can also be transcripts.
  4. Choose Submit encounter. Confirm the upload and use Use this encounter in a group, or give participants the Activity/Case labels to find it in their own accounts.

Start with a small note. The hosted demo currently limits the whole upload request to 16 MB, even if the application displays a larger file allowance. Arrange larger media with the operator before the session.

If something gets in the way

Keep your place. Ask for help.

I cannot sign in, or I do not have an account

Use the latest hosted URL and the account assigned to you. Check copied spaces and capitalization in the password. There is no public registration; the Create Account button returns an error. Ask your facilitator for access or a reset; do not post credentials in an issue or chat.

I do not see any sample encounters or a starter rubric

Check Groups → Search Encounters, leave the deployment default selected, and clear unexpected filters. Ask the facilitator which activity/case and rubric are ready. Do not substitute personal records or upload another participant’s files.

The run is queued, slow or failed

Check Grading Runs and Details. Other participants share the hosted service and both model providers’ quotas. Avoid starting duplicates; if a run errors, wait a minute and retry once. Give the facilitator the run ID, the action you took and a sanitized error message; do not include passwords, keys or signed file links.

Which model produced my run?

Under Grading Runs, open the run’s Details and read the Model column under Cost Estimate. The runs list and the results page show the rubric name, group and start time, not the model or the rubric version, so note the start time before changing either.

A Wayfinder, Enhance or Transform request timed out

Check the refreshed rubric inventory for a completed upload or new version before resubmitting. If the interface asks you to acknowledge the inventory, use “I reviewed this refreshed inventory — allow another request” only after checking it. The prepared rubric remains available for the main walkthrough, and route A needs no model call.

The page refreshed—did I lose my work?

Check your groups, uploaded rubrics and existing runs before recreating anything. Saved reviews should remain; unsubmitted edits and Wayfinder chat history may not. Refresh the run and inspect its state before trying another request.

Can I upload my own rubric or note?

Yes. Step 7 covers five ways to change or create a rubric in your own account, including the downloadable template. For new notes, follow Bring your own note: give fictional demo notes to the facilitator for the shared library. Media needs a host check first.

Can I install this on my laptop?

Follow the assisted setup guide. You can complete this hosted session with your browser; no local installation is required.

A useful session ends here.

  • You can explain what a group, rubric and grading run each do.
  • You have checked one assessment against its source note, saved a review and opened an Excel export.
  • You have changed one thing, run again, and can say what changed between the two runs.
  • You can tell which model produced each run, and why the human review, not the model, is the record.
